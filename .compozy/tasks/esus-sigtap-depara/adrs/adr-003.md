# ADR-003: Exact (secao, descricao) lookup with real e-SUS sections

## Status

Accepted

## Date

2026-07-26

## Context

Municipal spreadsheets visually mixed “Pequenas cirurgias”, rapid tests, and medication administration. e-SUS CSVs store these as distinct `secao` values. Unifying under one section would break exact joins to `esus_indicadores_raw`. Label-only lookup risks collisions across sections.

## Decision

- Seed `esus_procedimento_map.secao` with **real e-SUS section names** as produced by `parse_esus_csv.py` (e.g. `Procedimentos / Pequenas cirurgias`, `Procedimentos - Teste rápido`, `Procedimentos - Administração de medicamentos`, odontological `Procedimentos`, native `Outros procedimentos (SIGTAP)`, etc.).
- Consumer lookup contract: **exact match** on `(secao, descricao_esus)` where `status = 'ativo'`, join `procedimentos` for `codigo_sigtap`.
- Unmapped rows: **silent skip** (no error, no warning list in MVP).

## Alternatives Considered

### Alternative 1: Single UI section for all minor-procedure labels

- **Description**: Store everything under `Procedimentos / Pequenas cirurgias`.
- **Pros**: Matches spreadsheet grouping.
- **Cons**: Breaks exact match to raw imports for teste rápido / medicação.
- **Why rejected**: User selected real e-SUS sections after clarifying lookup impact.

### Alternative 2: Label-only lookup

- **Description**: Resolve by `descricao_esus` ignoring section.
- **Pros**: Tolerates section drift.
- **Cons**: Ambiguous duplicates (e.g. “Drenagem de abscesso” in clinical vs odonto).
- **Why rejected**: User selected exact `(secao, label)`.

## Consequences

### Positive

- Deterministic join to imported indicators.
- Seed sections match operator mental model from e-SUS reports.

### Negative

- Spreadsheet rows must be split into correct sections during seed curation.
- Section rename in future e-SUS versions requires new map rows.

### Risks

- Mis-assigned section in seed → silent miss in export — mitigate with docs + CRUD correction.

## Implementation Notes

Document the section list and exact-match rule in `docs/esus-sigtap-depara.md` and in-app help. Native SIGTAP sections: parse `"NNNNNNNNNN - DESCRICAO"` into `procedimentos.codigo_sigtap` + map row with full description text as `descricao_esus`.
