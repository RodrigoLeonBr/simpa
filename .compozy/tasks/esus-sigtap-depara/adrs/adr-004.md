# ADR-004: Dual consumption — consolidado + on-demand JSON/CSV export

## Status

Accepted

## Date

2026-07-26

## Context

PRD requires MVP use of the mapping for both analytical cross-reference and procedure export. No export endpoints exist today. Dashboard payload is built by `consolidate_dashboard.py` into `dados_consolidados`. Planning needs downloadable CSV and API JSON.

## Decision

1. **Analytics (persisted):** extend `consolidate_dashboard.py` to emit `modulos.atencao_primaria_esus.procedimentos_mapeados[]` (or equivalent under APS module) with `{secao, descricao_esus, codigo_sigtap, descricao_sigtap, quantidade}` via exact map lookup; silent skip unmapped.
2. **On-demand API:** `GET` endpoint returning the same mapped rows for filters (competencia, unidade, equipe), plus `Accept` / `?format=csv` (or sibling path) for CSV download.
3. **Frontend:** Cadastros CRUD page + export trigger (download CSV from API); short in-app help; repo guide `docs/esus-sigtap-depara.md`.

MVP CSV columns: competencia, unidade, equipe, secao, descricao_esus, codigo_sigtap, descricao_sigtap, quantidade.

## Alternatives Considered

### Alternative 1: Consolidated payload only

- **Description**: Only enrich `dados_consolidados`.
- **Pros**: One write path.
- **Cons**: No dedicated export download; couples export to full recompute.
- **Why rejected**: User wanted on-demand endpoint as well.

### Alternative 2: On-demand only (no consolidado change)

- **Description**: Export/query API only; dashboard unchanged.
- **Pros**: Smaller consolidator change.
- **Cons**: Painel cannot show mapped APS procedures without extra calls.
- **Why rejected**: User chose both surfaces.

### Alternative 3: BPA-layout export

- **Description**: DATASUS BPA-C/I file.
- **Pros**: Closer to billing submission.
- **Cons**: Out of PRD MVP non-goals (full BPA certification).
- **Why rejected**: User chose internal JSON + CSV.

## Consequences

### Positive

- Shared lookup logic can live in one backend/Python helper used by consolidator and API.
- Operators get immediate CSV without waiting for BPA-grade export.

### Negative

- Contract JSON v3.1.0 gains a new array — frontend types must update.
- Two code paths must stay semantically identical (docs + shared function).

### Risks

- Drift between Python consolidator and Node export if duplicated — prefer one shared SQL view or call Python from Node (existing `consolidador.js` pattern) / single SQL query used by both.

## Implementation Notes

Prefer a single SQL query or shared service function for “map raw indicators → SIGTAP rows”. Mount export under `/api/` (e.g. `/api/procedimentos/export` or `/api/cadastros/procedimentos/export`). Soft-delete inactive maps excluded from consumers.
